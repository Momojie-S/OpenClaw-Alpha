# 处理用户反馈任务流程

你需要在任务目录下创建 `progress.md` 记录进度。

---

## 流程阶段

| Step | 内容 | 输出 |
|------|------|------|
| 0. 进度 | 创建或检查进度文档 | progress.md |
| 1. 需求分析 | 区分表面需求 vs 真实需求 | 需求分析 |
| 2. 技术评估 | 检查是否符合项目规范 | 技术评估 |
| 3. 处理决策 | 采纳/调整后采纳/不采纳/待讨论 | 决策结论 |
| 4. 输出结果 | 将处理结果输出到 session 上下文 | 结果字段 |

---

## 核心原则

- 理解真实需求，而非照搬方案
- 规范优先，用户建议只是参考
- 不在本次对话中立即实现
- **渐进式填写，完成当前阶段后才填写下一阶段的具体任务**

---

## 进度模板

```markdown
# 用户反馈：XXX

- **反馈来源**：
- **反馈时间**：

## Step 0: 进度
- [ ] 创建或检查进度文档是否存在（progress/YYYY-MM-DD-{反馈主题}.md）

## Step 1: 需求分析
- [ ] 分析表面需求
- [ ] 识别真实需求

## Step 2: 技术评估
（根据 Step 1 的需求分析填写）
- [ ] 调研当前框架是否满足
- [ ] 调研额外方案

## Step 3: 处理决策
- [ ] 做出处理决策

## Step 4: 输出结果
- [ ] **必须**：更新反馈 JSON 文件（使用任务消息中的 `<json_path>` 路径），添加 `decision` 和 `reason` 字段
- [ ] 在 `progress.md` 中记录处理过程和详细分析

**⚠️ 重要**：必须更新反馈 JSON 的 `decision` 字段，否则 Backend 无法检测完成状态，不会发送通知。

## 状态
- **当前步骤**：（Step 1-4）
- **处理结果**：（进行中/采纳/调整后采纳/不采纳/已解决/重复/待讨论）
- **优先级**：（P0/P1/P2/P3）
- **下一步**：（当前步骤完成后要做什么）

## 需求分析
- **表面需求**：
- **真实需求**：
- **场景上下文**：

## 技术评估
（是否符合规范，是否需要调整）

## 结论
（最终决策及理由）
```

---

## 输出格式要求

处理完成后，需要更新反馈 JSON 文件（使用任务消息中提供的 `<json_path>`），添加以下字段：

- `decision` - 决策结果
- `reason` - 决策理由

其他内容（表面需求、真实需求、技术评估、下一步行动等）记录在 `progress.md` 中即可。

**decision 取值说明**：

- `采纳`：用户方案完全符合项目规范，可以直接按用户建议实施
- `调整后采纳`：用户需求合理，但方案需要调整才能符合规范（如技术实现方式、数据源选择等）
- `不采纳`：不符合项目规范或需求不合理
- `待讨论`：信息不足或需要进一步沟通确认

**更新 JSON 示例**：

```json
{
  "id": "abc123",
  "source_user": "Momojie",
  "decision": "采纳",
  "reason": "符合项目规范，需求合理，建议创建开发任务实现",
  ...
}
```
